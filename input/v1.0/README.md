# 访客系统版本基线

本分支保存「访客系统」需求侧完整产出物，按版本独立存放；**V1.0 已封版**，需求基线冻结为开发唯一输入。

## 版本一览

| 版本 | 状态 | 封版时间 | 计数（REQ / US / TC） |
|------|------|----------|----------------------|
| V1.0 | 已封版 | 2026-10-12 17:30:00 | 45 / 49 / 107 |

> 需求域码：PT 访客预约 / AP 预约审批 / AT 到访登记 / GV 访客管理 / VS 访问统计 / LG 访客权限 / AN 公告通知 / BD 基础数据 / OR 组织与权限 / NT 通知 / SM 系统管理。

## 目录结构

| 目录 / 文件 | 说明 |
|-------------|------|
| `需求规划/` | 阶段一：名词统一、功能模块地图、简易交互原型、阶段一出口确认、版本规划 |
| `需求梳理/` | 阶段三：详细需求清单、可测性审查报告、待拍板清单、REQ 清单、高保真原型 |
| `用户故事/` | V1.0 用户故事（US） |
| `测试用例/` | V1.0 测试用例（TC）、US×TC 交叉验证报告 |
| `PRD/` | V1.0 需求文档 PRD、封版人工核对文档 |
| `assets/` | 功能模块地图（html / json / png / svg） |
| `版本看板.md` | 各版本环节状态 / gate 时刻 / 计数 / 文件索引总表 |
| `变更清单.md` | 封版后变更登记（append-only，不回写封版 PRD 正文） |

## 治理说明

- 产出依据 `requirement-pipeline`（版本独立闭环模型）方法论生成。
- 每份产出维护「一物一 Log」修改记录（`*-修改记录.md`）。
- 封版后任何变更一律登记到 `变更清单.md`，**不回写封版 PRD 正文**。
