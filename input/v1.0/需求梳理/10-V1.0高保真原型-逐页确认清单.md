## 二、逐页核对点（逐页 sign-off）

> 「🔎 核对点」= 该页原型已呈现、需用户确认的关键口径；「□」供用户逐项打勾。

### 1. PT 工作台 · 待办 · 消息 · 二维码（REQ-PT-001 … 005）
- [ ] REQ-PT-001 统一登录与身份识别：admin/guard **账号**、host **工号**+密码；连续失败 **5 次锁 10min**（按账号计数、自动解锁）；密码 ≥6、不强制复杂度；visitor 经 H5 **免密**进入（凭服务端下发的**不可枚举会话令牌**，不走后台登录，D5/D30）；6 位短码**仅用于现场核验比对、不得作为读取个人详情的凭证**（D30）
- [ ] REQ-PT-002 角色工作台路由：登录后按角色进 admin/guard/host 工作台；visitor **无后台工作台**，直接进手机端 VS
- [ ] REQ-PT-003 我的待办聚合：待审核 / 待核验 / 异常待处理，带数量徽标，点击进对应处理页（**「异常待处理」＝异常记录状态机为 `待处理`**，状态机 `待处理/已处理/已忽略`，D36；处置后即退出待办）
- [ ] REQ-PT-004 通知与消息入口：站内消息入口，可标记已读；新增显**红点**、已读持久
- [ ] REQ-PT-005 访客申请入口二维码：后台生成（指向 H5「我要申请」），可查看/**下载 PNG**/打印；**入口 URL＝系统参数可配**（默认域名 + `/h5/apply`，D13）

### 2. AP 访客预约（REQ-AP-001 … 005）
- [ ] REQ-AP-001 提交来访预约：采集 类型/姓名/手机号/证件号/被访人/到访时段(起止)/事由/车牌(可选)/随行明细；**手机号 `^1\d{10}$`、证件号 身份证 18 位（含校验位）/ 其他 5–20 位、到访时段 起<止·同一自然日不可跨天·时长 15min–在校上限（默认 240min）**（D6）；提交成功 →「待审核」+ 触发通知
- [ ] REQ-AP-002 随行人员逐人明细：逐人 姓名/关系/证件号；**明细 ≤10 条（含主共 ≤11 人）**；证件号同主访客规则；黑名单预检**覆盖随行**（任一命中整单按 D4 软提示）（D9）
- [ ] REQ-AP-003 预约信息校验：①必填 ②时段须在启用「可预约时段」内且未过期（`当前 < 时段起`）③黑名单预检 ④**同一访客同时段防重复**——重叠=**闭区间相交(含端点相接即冲突)**、「**未完结集**」=**{待审核, 已改期, 已通过, 已到访(在校中)}**（**D26** 补入「已改期」，与是否终态解耦）；**终态 {已拒绝, 已过期, 已取消} 后可重新发起**、「已离校」＝可回退准终态不参与防重复（D26）；禁入与可预约冲突**禁入优先**（D7/D8/D16/D26）
- [ ] REQ-AP-004 预约修改/取消：到访前可改期/取消；权限 访客本人/被访人/管理员；**已到访、已离校不可改**；已到访操作返回 409
- [ ] REQ-AP-005 预约状态跟踪：展示 8 态枚举 + 各次流转时间；与台账**同源**（§3.24）

### 3. AT 被访人审核（REQ-AT-001 … 004）
- [ ] REQ-AT-001 待审核列表：**仅本人**相关预约（对象级隔离，服务端强制 §3.22）；host 仅见本人、admin 见全校（兜底）；越权读他人 403 + 留痕
- [ ] REQ-AT-002 审核处理：同意/拒绝/改期；**拒绝原因 必填·2–100 字·自由文本不枚举**；**改期须给新时段且重过 REQ-AP-003 全部校验（防重复校验排除本预约自身，D29）**；**改期＝提议改期**：通知访客确认 → 确认后回「待审核」（D1/F-007a）；改期次数**不限**（D1）；**提议后超 3 小时未确认 → 定时任务自动转「已过期」（终态）、须重新申请、留痕**（D38）；重复处理 409（D10/D1/F-007a/D29/D38）
- [ ] REQ-AT-003 审核人可配置：默认被访教职工；可配置为管理员或指定人（落 BD）；**配置生效后新预约流转到指定审核人**（前向不追溯）
- [ ] REQ-AT-004 审核留痕：每次审核写操作日志 谁/何时/决定/原因；可按预约筛

### 4. GV 门卫核验放行（REQ-GV-001 … 006）
- [ ] REQ-GV-001 现场核验：核对 身份信息 + 预约/凭证一致性 + 是否在有效时段（**有效时段＝核验窗口＝预约时段 ± 有效时段缓冲（默认 15min 可配）**，D28）；**V1.0 仅人工核验**（不含自动识别，归 V1.1，D3）；一致且在时段内放行，否则拦截提示（D3/D28）
- [ ] REQ-GV-002 放行与现场登记：有预约→核验放行；无预约→**现场登记**（复用 AP 采集项）后放行；记录时刻与放行人
- [ ] REQ-GV-003 访客凭证核销：核销 预约编号 + 二维码/短码 为已用，防重复；**短码=6 位数字、全局唯一、随预约生成、有效至预约终结**（终结＝终态 {已拒绝, 已过期, 已取消}，D26）；6 位短码**仅用于现场核验比对、不得作为读取个人详情的凭证**（D30）；重复核销拒绝放行（D13/D26/D30）
- [ ] REQ-GV-004 进校/离校登记：记录进/离校时刻；**允许当天多次进出**，「已离校」**非绝对终态＝可回退的准终态**（再进回「已到访(在校中)」，D26）；每次留痕；时刻精确到分钟（D12/D26）
- [ ] REQ-GV-005 异常上报：异常类型**4 类全集**＝黑名单命中/信息不符/强行闯入/**手动**上报超时未离（F-013）；写异常记录并通知管理员；异常记录带**状态机 `待处理/已处理/已忽略`**，处理权限＝管理员、处置说明必填、处置后退出待办（D36）；异常可查（F-013/D36）
- [ ] REQ-GV-006 门口当日视图：门卫只见当日/现场范围（当日预约、待核验、在校中）；不越界全院历史

### 5. VS 访客端 H5（REQ-VS-001 … 004）
- [ ] REQ-VS-001 我要申请：扫码/协助进入，填本人预约（复用 AP 采集项）；提交成功→待审核；无需下载 App
- [ ] REQ-VS-002 我的申请（查看）：查看**本人**状态与凭证（仅本人，服务端强制）；页内出示二维码供核验
- [ ] REQ-VS-003 安全告知/授权告知：提交前须阅读并勾选《安全告知》《个人信息授权告知》；**未勾选不可提交**；**每次提交均需确认（不记忆）**、留痕按预约（含时间戳）（D2/D19）
- [ ] REQ-VS-004 扫码进入：扫「申请入口二维码」直达「我要申请」；**兼容 iOS Safari 15+ / Android Chrome 近两年 / 微信内置浏览器，适配 320–480px**（D22）

### 6. LG 台账 · 在校清单 · 检索 · 导出（REQ-LG-001 … 004）
- [ ] REQ-LG-001 访客台账：全部来访记录汇总（谁/类型/何时来/找谁/何时走/状态）；admin 全校、guard 仅当日/现场；**分页 `page`(1)/`pageSize`(20,≤100)、默认按到访时间倒序、空数据 `{items:[],total:0}`**（D15）
- [ ] REQ-LG-002 在校（实时）清单：当前仍在校访客实时名单（谁/何时进/找谁/已在校多久）；进校入列、离校移出、准实时刷新；**按最后一次状态取数**（D12）
- [ ] REQ-LG-003 多条件查询/检索：按 姓名/证件号/手机号/时段/被访人/类型/状态 检索；与台账同源；**脱敏后仅 admin 可精确命中检索**（精确命中但不回显完整证件号）（D14）；**1 万条内响应 < 2s**（D23）

### 7. AN 统计分析（REQ-AN-001 … 002）
