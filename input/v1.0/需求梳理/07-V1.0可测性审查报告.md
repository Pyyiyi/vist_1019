## 二、整体判断

材料完整度高：V1.0 边界骨架（11 域 45 条功能）逐条给出「做什么 / 关键规则 / 交互与数据 / 验收口径 / 优先级 / 角色」，且通过附件 D–F 把规则六要素、枚举穷举、状态三件套、派生同源、可配四件套做了闭合登记，可直接支撑大多数用例的**预期结果**断言。

主要影响面有三：

1. **字段级校验与边界值**（建议 004/007/008 等）——清单给了「采集哪些字段」，但**未逐字段写明必填/长度/格式/上下限**，边界与等价类用例目前只能依赖推断，需补「字段规格表」。
2. **状态机个别迁移**（建议 001）——8 态全集与驱动已列，但「已改期」的进入条件、改期后是否重回待审核、是否需访客确认尚未定（清单已登记 WAIT-1）。
3. **主数据删除与脱敏检索两条潜规则**（建议 009/012）——软状态已规范，但**硬删除策略**与**G11 脱敏后证件号还能否被检索**未写，可能造成数据一致性/隐私口径冲突。

当前最值得优先对齐的是上述 1、2 两点，因其同时影响**用例数量**与**回归范围**。

## 三、建议调整清单

### 建议 001｜状态机「已改期」的进入与离开口径

- 优先级：**P0**
- 建议类型：状态流转
- 依据位置：`06` §F-AT-02、附件 D·C「状态类·三件套」（原 `已改期` 行注「改后回到待审核」与表体并列，措辞需二选一）
- 当前材料表现：附件 D·C 列「已改期」的驱动＝「审核『改期』（给新时段，**改后回到待审核**）」，同时 8 态全集又把「已改期」列为独立状态；F-AT-02 验收只写「处理后状态迁移」。清单已登记 **WAIT-1**（已改期是否单列 + 改期后是否需访客确认）。
- 建议调整：建议明确①「已改期」是**独立状态**还是**瞬时态**（改期即回到待审核）；②改期后是否需**访客重新确认**；③改期次数是否限制。三选一定稿后同步附件 D·C。
- 对测试工作的影响：直接决定状态机用例的**状态数与迁移边数**，影响「改期」分支的全部回归用例；不定稿则无法穷举合法/非法迁移。
- 待确认对象：产品、业务
- 确认状态：待确认

### 建议 002｜黑名单命中的处理时点与结果

- 优先级：**P0**
- 建议类型：主流程与业务规则
- 依据位置：`06` §F-AP-03、§F-GV-01、附件 D·A 第 2 条（已登记 WAIT-4）
- 当前材料表现：附件 D·A 建议「提交时**软提示可提交并标记**；核验时**硬拦不放行**」，但清单正文 F-AP-03 只写「黑名单预检（命中见附件 D·A）」，验收口径未给「命中后提交按钮是否可点、记录是否落入待审核」。**安全为本系统核心目标**，此处结果直接决定放行与否。
- 建议调整：建议明确①提交命中黑名单 → 允许提交并打标，或直接拒收；②核验命中 → 硬拦且不给放行，是否可管理员**临时放行**（白名单/override）；③命中后的通知对象与审计事件。
- 对测试工作的影响：影响「提交」「核验」两条核心流程的**预期结果断言**与黑名单用例边界；不定稿会导致同一用例两种结论。
- 待确认对象：产品、业务、安全责任人
- 确认状态：待确认

### 建议 003｜登录「账号 / 工号」口径与失败锁定恢复机制

- 优先级：P1
- 建议类型：权限前置 / 边界条件
- 依据位置：`06` §F-PT-01；`01-名词统一.md` 角色定义
- 当前材料表现：F-PT-01 写「账号/工号 + 密码登录……连续失败 5 次锁定 10 分钟」；token 8h。**未明确**各角色分别用「账号」还是「工号」，也未写锁定到期后是否**自动解锁**、计数是否**按账号还是按 IP**、锁定期间提示文案、密码长度/复杂度。
- 建议调整：建议明确①各角色登录标识（admin/guard 用账号、host 用工号）；②锁定计数维度（账号）、解锁方式（10 分钟自动解锁）；③密码策略（长度/复杂度，若无则显式注明「V1.0 不强制」）。
- 对测试工作的影响：影响登录用例的**等价类**（合法/非法标识）、锁定边界（第 4/5/6 次）、解锁后重试，以及 token 过期后行为。
- 待确认对象：产品、研发
- 确认状态：待确认

### 建议 004｜预约采集字段的逐字段必填与格式规则

- 优先级：P1
- 建议类型：数据规则 / 边界条件
- 依据位置：`06` §F-AP-01、§F-AP-02、附件 A
- 当前材料表现：F-AP-01 列出「访客类型、姓名、手机号、证件号、被访人、到访时段（起止）、事由、车牌（可选）、随行明细」，但**未逐字段写**必填/选填、长度、格式。附件 A 只覆盖 8 个「不常见/易混淆」字段，常见字段（姓名/手机号/证件号/事由）格式未定义。
- 建议调整：建议补一张**字段规格表**：每字段〔界面名 · 存储字段 · 必填 · 类型 · 长度 · 格式/校验 · 默认值 · 帮助文案有无〕。手机号（11 位）、证件号（身份证 18 位 or 其他证件放行）、姓名（长度）、事由（长度）、时段（起止先后、可否跨天、时长上下限）逐条给出。
- 对测试工作的影响：直接影响必填缺失、格式错误、超长/边界值、空值等一大批等价类与边界用例；无规格表则边界值无处取证。
- 待确认对象：产品、研发
- 确认状态：待确认

### 建议 005｜「可预约时段」与「未过期」的判定口径

- 优先级：P1
- 建议类型：数据规则 / 外部依赖
- 依据位置：`06` §F-AP-03（②「到访时段须落在启用『可预约时段』内且未过期」）、§F-BD-03（可预约时段/禁入时段）
- 当前材料表现：F-BD-03 列「可预约时段、有效时段缓冲、禁入时段、在校时长上限」，但**未定义**「可预约时段」的数据形态（按星期几 + 时段？按日期区间？），也未写「未过期」＝当前时间 < 预约时段起 还是 < 预约时段止。

- 对测试工作的影响：影响「时段校验」分支的等价类与边界（刚好在边界上/跨越禁入时段/已过期），以及 F-BD-03 配置变更后的回归。

### 建议 006｜「防重复提交」的重叠与未终结定义

- 优先级：P1
- 建议类型：主流程与业务规则
- 依据位置：`06` §F-AP-03（④）、附件 D·A 第 4 条

- 建议调整：建议明确重叠判定算法（含/不含端点、是否计入有效时段缓冲），并列全「未终结」状态集合与「已终结」集合。

### 建议 010｜进校 / 离校的多次登记（中途外出再入）

- 优先级：P1
- 建议类型：状态流转 / 边界条件
- 依据位置：`06` §F-GV-04、附件 D·C（`已到访(在校中)` / `已离校`）

- 对测试工作的影响：影响进出校用例的重复登记分支、在校实时清单（G1）的取数与移出断言。
- 待确认对象：产品、业务
- 确认状态：待确认

### 建议 012｜G11 脱敏与台账「按证件号检索」的互斥口径

- 优先级：P1
- 建议类型：数据规则 / 权限前置
- 依据位置：`06` §F-SM-02（到期自动脱敏、隐去证件号/人像）、§F-LG-03（按证件号/手机号检索）

- 确认状态：待确认

### 建议 014｜终态后能否重新发起预约

- 建议类型：状态流转 / 主流程
- 依据位置：`06` 附件 D·C（终态：已离校/已拒绝/已取消/已过期）、§F-AP-04
- 当前材料表现：附件 D·C 写 4 态为终态、不可再流转到「已到访」，但**未写**终态之后是否允许访客用**同一时段再提交新预约**（与建议 006 防重复的「未终结」集合相关）。
- 建议调整：建议明确终态记录与「新预约」的关系：允许重新发起为**新记录**（保留历史），且旧终态不参与防重复判定。
- 对测试工作的影响：影响「取消/拒绝/过期后再预约」的用例与防重复边界。
- 待确认对象：产品
- 确认状态：待确认

### 建议 015｜HTTP 错误码与返回体约定系统化

- 优先级：P2
- 建议类型：数据结构 / 接口
- 依据位置：`06` §F-PT-01（401/403）、§F-AT-02（409）、§F-AP-04（409）、附件 C（403）
- 当前材料表现：清单零散出现 401/403/409，但**未系统列出**各错误场景 → 状态码 + 错误体结构（code/message/field）的映射表。
- 建议调整：建议补一张**错误约定表**：场景（未登录/越权/状态冲突/校验失败/不存在）→ HTTP 码 → 错误体字段。
- 对测试工作的影响：统一接口用例的**状态码断言**与错误提示断言，减少逐接口猜测。
- 待确认对象：研发
- 确认状态：待确认

## 六、建议补充的验收证据

- **正常主流程**：预约（含 G4 随行）→ 审核通过 → 核验放行 → 进校 → 离校 → 台账/在校清单各阶段的状态与时刻截图或接口返回样例。
- **边界与时间**：连续失败 5 次锁定、时段起止边界、有效时段缓冲 ±、在校时长上限触达、留存 90 天脱敏临界（第 90/91 天）。
- **异常与恢复**：黑名单命中（提交/核验两时点）、重复审计返回 409、重复核销提示、越权 403、token 过期 401。
- **权限与数据隔离**：host 仅本人（越权读他人 403 + 审计）、visitor 仅本人、guard 仅当日/现场、adminOnly 资源非 admin 403。
- **页面/原型状态**：VS 移动端空状态/提交失败/凭证出示；工作台待办徽标；门口当日视图。
- **日志、埋点或后台数据**：审计条目最小字段（谁/何时/对象/动作/结果）、通知生成记录、导出脱敏列。
