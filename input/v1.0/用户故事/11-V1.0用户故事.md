## 二、US 清单（49 条 · 11 域）

> 每条形如：**作为** <角色>，**我希望** <能力>，**以便** <价值>；附「优先级 / 溯源（REQ + D）/ 承载页面 / 验收标准（AC）」。
> 术语口径见 `需求规划/01-名词统一.md`（D24：核验/核销/放行）。

### PT · 平台门户（6 条）

#### US-PT-001 · 后台用户登录与身份识别
- **作为** 管理员 / 门卫 / 被访教职工，**我希望** 用**账号**（admin/guard）或**工号**（host）＋密码登录并识别我的身份，**以便** 进入与角色匹配的后台。
- **优先级**：P0　**溯源**：REQ-PT-001（D5）　**承载页面**：原型 `#page-pt`（登录）
- **验收标准**：
  - AC1（登录成功）：Given 账号存在且状态 active，When 提交正确凭据，Then 登录成功并返回身份与角色。
  - AC2（连续失败锁定）：Given 同一账号，When 连续输错密码达 **5 次**，Then 该账号**锁定 10 分钟**（按账号计数、**自动解锁**），期间正确密码亦拒绝。
  - AC3（密码策略）：密码长度 **≥6**、**不强制**复杂度；不满足即拒绝。
  - AC4（停用账号）：账号被停用（软状态），When 尝试登录，Then 返回 **401**。

#### US-PT-002 · 访客免密进入（H5）
- **作为** 访客，**我希望** 凭服务端下发的**不可枚举会话令牌**免密进入 H5，**以便** 无需注册账号即可查看/出示我的预约。
- **优先级**：P0　**溯源**：REQ-PT-001（D5/D30）　**承载页面**：原型 `#page-vs`
- **验收标准**：
  - AC1：Given 访客持有效的**不可枚举会话令牌**（服务端下发、绑定该预约），When 打开 H5，Then 直接进入「我的申请」，**不走**后台登录。
  - AC2：visitor **不占用**后台账号体系（无 web/后台工作台）。
  - AC3（凭证边界·D30）：**6 位短码仅用于现场核验比对，不得作为读取个人详情的凭证**。

#### US-PT-003 · 角色工作台路由
- **作为** 后台用户，**我希望** 登录后按角色进入对应工作台，**以便** 只看到与我职责相关的功能。
- **优先级**：P0　**溯源**：REQ-PT-002　**承载页面**：原型导航按角色显隐
- **验收标准**：
  - AC1：admin → 管理员工作台（全模块）；guard → 门卫工作台；host → 教职工工作台；visitor → **直接进** H5 VS（无后台）。
  - AC2：adminOnly 清单与基线一致（附件 C）；非授权角色访问受限模块，前端隐藏**且**服务端 403（§3.22）。

#### US-PT-004 · 我的待办聚合
- **作为** 后台用户，**我希望** 在工作台看到待审核（host/admin）、待核验、异常待处理的聚合与数量徽标，**以便** 快速进入处理。
- **优先级**：P1　**溯源**：REQ-PT-003（D36）　**承载页面**：原型 `#page-pt`
- **验收标准**：
  - AC1：各待办项显示数量徽标，数字随数据实时变化。
  - AC2：点击某项进入对应处理页（待审核→AT、待核验→GV、异常→GV）。
  - AC3（异常待处理口径·D36）：「异常待处理」＝异常记录**状态机为 `待处理`** 的条目（状态机 `待处理/已处理/已忽略`，见 US-GV-006）；处置后（已处理/已忽略）即**退出待办**、徽标递减。

#### US-PT-005 · 通知与消息入口
- **作为** 后台用户，**我希望** 有站内消息入口并可标记已读，**以便** 及时获知与我相关的事件。
- **优先级**：P1　**溯源**：REQ-PT-004（NT）　**承载页面**：原型 `#page-pt`
- **验收标准**：
  - AC1：有新增消息时显示**红点**；已读状态**持久**保存。
  - AC2：点击消息进入对应业务对象。

#### US-PT-006 · 访客申请入口二维码
- **作为** 管理员，**我希望** 后台能生成/查看/下载（PNG）/打印指向 H5「我要申请」的入口二维码，**以便** 供访客扫码发起预约。
- **优先级**：P1　**溯源**：REQ-PT-005（D13）　**承载页面**：原型 `#page-pt`
- **验收标准**：
  - AC1：二维码指向 H5「我要申请」；可查看、下载 PNG、打印。
  - AC2：**入口 URL＝系统参数可配**（默认＝部署域名 + `/h5/apply`，D13）；改参数后新生成二维码随之生效。

### AP · 预约（6 条）

#### US-AP-001 · 提交来访预约
- **作为** 访客（或协助录入的被访人/管理员），**我希望** 填写来访预约并提交，**以便** 到访前完成登记、进入审核。
- **优先级**：P0　**溯源**：REQ-AP-001（D6）　**承载页面**：原型 `#page-ap` / `#page-vs`
- **验收标准**：
  - AC1（采集项）：类型 / 姓名 / 手机号 / 证件号 / 被访人 / 到访时段（起止）/ 事由 / 车牌（可选）/ 随行明细。
  - AC2（字段规格，按 §0.5·A）：手机号 `^1\d{10}$`；证件号＝身份证 **18 位含校验位** / 其他 **5–20 位**；到访时段 **起<止**、**同一自然日不可跨天**、时长 **15min–在校上限（默认 240min）**。
  - AC3：必填缺失/格式错即**拦**，不提交。
  - AC4：提交成功 → 状态置 **「待审核」** 并**触发通知**（通知被访人）。

#### US-AP-002 · 随行人员逐人明细
- **作为** 访客，**我希望** 逐人登记随行人员的 姓名/关系/证件号，**以便** 随行人员一并核验放行。
- **优先级**：P0　**溯源**：REQ-AP-002（D9，G4）　**承载页面**：原型 `#page-ap` / `#page-vs`
- **验收标准**：
  - AC1：到访人数 = 1 + 明细条数。
  - AC2：明细 **≤10 条**（含主访客 **≤11 人**）；超限即拦。
  - AC3：随行证件号**同主访客规则**校验（AC 同 US-AP-001·AC2）。
  - AC4：黑名单预检**覆盖随行**——**任一**随行命中，整单按 D4 处理（软提示）。

#### US-AP-003 · 预约信息校验
- **作为** 系统，**我希望** 在提交时对预约做一致性/合规校验，**以便** 只让合规预约进入审核。
- **优先级**：P0　**溯源**：REQ-AP-003（D7/D8/D16/D26）　**承载页面**：原型 `#page-ap` / `#page-vs`
- **验收标准**：
  - AC1（必填）：必填项齐备。
  - AC2（时段可用且未过期）：到访时段落在**启用**的「可预约时段」内，且 **未过期**（`当前时间 < 到访时段起`）；否则拦。
  - AC3（黑名单预检）：命中即按 D4 软提示（不拦提交）。
  - AC4（防重复）：同一访客同一时段**重叠＝闭区间相交（含端点相接即冲突）**，「**未完结集**」＝ **{待审核, 已改期, 已通过, 已到访(在校中)}**（**D26** 补入「已改期」，与「是否终态」解耦）命中即**拒绝提交**。
  - AC5（终态可重发）：预约处于**终态 {已拒绝, 已过期, 已取消}** 后，同访客/同时段**可重新发起**新预约；旧终态不参与防重复。**「已离校」＝可回退的准终态、不参与防重复**（D26）。
  - AC6（优先级）：禁入时段与可预约时段冲突时，**禁入优先**。

#### US-AP-004 · 预约改期
- **作为** 访客本人 / 被访人 / 管理员，**我希望** 在到访**前**把预约改期，**以便** 调整到访时间。
- **优先级**：P1　**溯源**：REQ-AP-004　**承载页面**：原型 `#page-ap`
- **验收标准**：
  - AC1（权限）：仅 访客本人 / 被访人 / 管理员 可操作。
  - AC2（可改边界）：**已到访、已离校不可改**；改期成功**留痕**。
  - AC3：新时段须**重过** REQ-AP-003 全部校验，且防重复校验**排除本预约自身**（D29）。

#### US-AP-005 · 预约取消
- **作为** 访客本人 / 被访人 / 管理员，**我希望** 在到访**前**取消预约，**以便** 终止不再进行的来访。
- **优先级**：P1　**溯源**：REQ-AP-004　**承载页面**：原型 `#page-ap`
- **验收标准**：
  - AC1：到访前可取消，成功置「已取消」并**留痕**。
  - AC2：**已到访**状态下发起取消，返回 **409**。

#### US-AP-006 · 预约状态跟踪
- **作为** 访客 / 被访人，**我希望** 查看预约当前状态（8 态枚举）及各次流转时间，**以便** 掌握进度。
- **优先级**：P1　**溯源**：REQ-AP-005（LG 同源 §3.24）　**承载页面**：原型 `#page-vs` / `#page-ap`
- **验收标准**：
  - AC1：展示 8 态枚举（待审核/已通过/已拒绝/已改期/已过期/已到访(在校中)/已离校/已取消）与各次流转时间。
  - AC2：状态实时随流转更新，与**台账同源**（复用状态机唯一定义源）。

### AT · 审核（4 条）

#### US-AT-001 · 待审核列表（对象级隔离）
- **作为** 被访教职工，**我希望** 只看到**与我相关**的待审核预约；**作为** 管理员，**我希望** 看到全校兜底，**以便** 完成审核。
- **优先级**：P0　**溯源**：REQ-AT-001（F-008/§3.22）　**承载页面**：原型 `#page-at`
- **验收标准**：
  - AC1：host **仅见本人**相关预约；admin **见全校**（兜底）。
  - AC2（服务端强制）：越权读他人预约返回 **403** 并**写「越权拦截」审计**。
  - AC3（审核人归属校验·F-008）：权限判定＝**审核人归属校验**（预约解析出的审核人＝当前用户，或当前用户为被访人/管理员）；**不写死 `host_id===teacherId`**，兼容指定审核人场景。

#### US-AT-002 · 审核处理（同意/拒绝/改期）
- **作为** 被访教职工 / 管理员，**我希望** 对待审核预约做 同意 / 拒绝 / 改期，**以便** 决定是否接待来访。
- **优先级**：P0　**溯源**：REQ-AT-002（D10/D1/F-007a/D29/D38）　**承载页面**：原型 `#page-at`
- **验收标准**：
  - AC1（同意）：置「已通过」并通知访客（审核结果通知**仅「通过/拒绝」**）。
  - AC2（拒绝）：**拒绝原因必填**、**2–100 字**、**自由文本不枚举**；置「已拒绝」并通知访客。
  - AC3（改期＝提议改期·D1/F-007a）：须给**新到访时段**且**重过 REQ-AP-003 全部校验（防重复校验排除本预约自身，D29）**；**通知访客确认 → 确认后回「待审核」**；改期次数**不限**（D1）。
  - AC4（改期超时·D38）：**改期提议后超 3 小时访客未确认 → 定时任务自动转「已过期」（终态）、须重新申请、留痕**。
  - AC5（幂等）：对同一已处理预约**重复处理**返回 **409**。

#### US-AT-003 · 审核人可配置
- **作为** 管理员，**我希望** 把某类/某人的审核人配置为 管理员或指定人（默认被访教职工），**以便** 分流审核职责。
- **优先级**：P2　**溯源**：REQ-AT-003（BD/F-008）　**承载页面**：原型 `#page-at` / `#page-bd`
- **验收标准**：
  - AC1：默认审核人＝被访教职工；可配为 管理员 / 指定人。
  - AC2：配置**生效后**新预约流转到指定审核人（**前向不追溯**）。
  - AC3（命中优先级·F-008）：多条配置同时命中时按**「最具体者优先」**（访客类型×校门×时段 > 全局），冲突时落点**唯一**。

#### US-AT-004 · 审核留痕
- **作为** 管理员，**我希望** 每次审核都写操作日志（谁/何时/决定/原因），**以便** 事后可查可追溯。
- **优先级**：P1　**溯源**：REQ-AT-004（SM）　**承载页面**：原型 `#page-at` / `#page-sm`
- **验收标准**：
  - AC1：每次审核写一条日志，含 操作人/时间/决定/原因。
  - AC2：可按**预约**维度筛选日志。

### GV · 门卫核验放行（7 条）

#### US-GV-001 · 现场核验
- **作为** 门卫，**我希望** 现场核对 身份信息 + 预约/凭证一致性 + 是否在有效时段，**以便** 决定是否放行。
- **优先级**：P0　**溯源**：REQ-GV-001（D3/D24/D28）　**承载页面**：原型 `#page-gv`
- **验收标准**：
  - AC1（V1.0 仅人工）：不包含自动识别（G2/G3 归 V1.1）；门卫人工比对。
  - AC2：一致且在有效时段 → 可放行；不一致/过期/黑名单 → **拦截并提示**。
  - AC3（有效时段＝核验窗口·D28）：**有效时段＝预约时段 ± 有效时段缓冲**（缓冲即核验窗口，默认 15min、可配）；超出窗口按过期拦截。

#### US-GV-002 · 有预约放行
- **作为** 门卫，**我希望** 对已预约且核验通过的访客放行，**以便** 完成进校。
- **优先级**：P0　**溯源**：REQ-GV-002　**承载页面**：原型 `#page-gv`
- **验收标准**：
  - AC1：核验通过后放行，记录**放行时刻**与**放行人**。

#### US-GV-003 · 无预约现场登记放行
- **作为** 门卫，**我希望** 对无预约访客做**现场登记**（复用 AP 采集项）后放行，**以便** 处理临时来访。
- **优先级**：P0　**溯源**：REQ-GV-002（AP 采集项/D27）　**承载页面**：原型 `#page-gv`
- **验收标准**：
  - AC1：登记项复用 AP 采集项与校验（同 US-AP-001/002/003）。
  - AC2：现场登记**生成来访记录**并放行，记录 放行时刻/放行人。
  - AC3（现场登记口径·D27）：门卫协助勾选《安全告知》《个人信息授权告知》（留痕同 US-VS-003）；**豁免** AP「未过期/未审核」校验（现场即时＝到访时刻即当前），**仍过黑名单预检**；凭证**生成即核销或不生成**。

#### US-GV-004 · 访客凭证核销
- **作为** 门卫，**我希望** 核销访客凭证（预约编号 + 二维码/短码），**以便** 防止重复使用。
- **优先级**：P0　**溯源**：REQ-GV-003（D13/D26/D30）　**承载页面**：原型 `#page-gv`
- **验收标准**：
  - AC1（短码规则）：**6 位数字、全局唯一、随预约生成、有效至预约终结**；**终结＝终态 {已拒绝, 已过期, 已取消}**（D26）。
  - AC2：**首次**核销成功并置为已用；**重复**核销**拒绝放行**。
  - AC3（凭证边界·D30）：6 位短码**仅用于现场核验比对，不得作为读取个人详情的凭证**。

#### US-GV-005 · 进校/离校登记（当天多次进出）
- **作为** 门卫，**我希望** 记录访客进校与离校时刻并在需要时允许当天多次进出，**以便** 准确反映在校状态。
- **优先级**：P0　**溯源**：REQ-GV-004（D12/D26）　**承载页面**：原型 `#page-gv` / `#page-lg`
