| A6 | 系统定位＝「预约→审核→核验→放行→离校→留痕」的**完整闭环** | 决定流程的主干 | 全闭环管控系统 | 可先做半个闭环 |

## B 组 · 角色与各自能看多少（来自「名词统一文档」）

> 这一组确认「每类人管什么、能看到谁的数据」——直接关系到安全与隐私。

| 编号 | 大白话释义 | 业务影响 / 谁受益 | 建议默认值 | 备选口径 |
|------|-----------|------------------|-----------|---------|
| B1 | **管理员**：维护账号、访客类型、黑名单、时段规则，看**全校**台账与统计 | 后台"总管家" | 全校可见可配 | —— |
| B2 | **门卫/保安**：只管**校门当日 / 现场**——核验、放行、登记进出、上报异常 | 一线值守 | 仅当日现场 | —— |
| B3 | **被访教职工**：**只能看与自己有关的**预约，处理同意/拒绝/改期 | 防"看到别人被谁访问" | **仅本人**（系统强制） | —— |
| B4 | **访客本人**：用**手机端（移动端 H5）**，**无 web 端**，**只能看自己的**预约与凭证，只有「我要申请」「我的申请（查看）」两项 | 保护访客隐私 | **仅本人**（系统强制）＋**移动端（无 web 端）** | —— |

> 说明：B3 / B4 的「仅本人」会在开发时**在服务器端强制**（不是只把按钮藏起来），越权访问会被拒绝并留痕——这是本系统「保安全」的底线（对应 §3.22，阶段三会写清具体接口）。
>
> **访客本人的入口形态（用户反馈 2026-10-10 已定；2026-10-12 进一步确认「全部在手机端」）**：访客本人使用**手机端（移动端 H5）**，**无任何 web / 后台端**（不经过后台统一门户，**全部在手机端完成**）；V1.0 仅承载「**我要申请**」「**我的申请（查看）**」两项。进入方式两种：① 到门口由门卫协助 / 现场登记；② **扫「申请入口二维码」自助进入**（二维码由后台生成、张贴于校门 / 公示处，扫码即打开手机端「我要申请」，**无需装 App**）。

## E 组 · 系统分几大块（来自「功能模块地图」）

> 这一组确认「系统一共分几个模块、每个模块大概干什么」——这是后面排版本、分开发的骨架。

**E1 · 一个统一入口**：角色登录后进各自的**工作台**（管理员台 / 门卫台 / 教职工台），待办事项集中显示（**访客本人无 web 端，不经过此处**）。建议默认值：保留。

**E2 · 六个业务模块（核心闭环）**

| 编号 | 模块 | 大白话：它干什么 | 建议默认值 |
|------|------|----------------|-----------|
| E2.1 | **访客预约** | 来访前填单（时段、事由、找谁、人数、车牌），可改可取消，能看到进度 | 要 |
| E2.2 | **被访人审核** | 老师处理属于自己的预约（同意/拒绝/改期），只看自己的 | 要 |
| E2.3 | **门卫核验放行** | 门口核对身份与预约、凭证核销、放行登记、进出校登记、异常上报 | 要 |
| E2.4 | **访客门户·我的申请与凭证（移动端·手机 H5，无 web 端）** | 访客**全部在手机端**完成，只有两项：「我要申请」（填单提交）+「我的申请（查看）」（看自己的预约、出示通行凭证、确认安全须知） | 要 |
| E2.5 | **访客台账与查询** | 全部来访记录汇总（谁/何时/找谁/何时走），可多条件查、可导出打印 | 要 |
| E2.6 | **统计分析** | 来访量按日/周/月与类型统计、异常统计、安全概览 | 要 |

**E3 · 四个基础模块（支撑底座）**

| 编号 | 模块 | 大白话：它干什么 | 建议默认值 |
|------|------|----------------|-----------|
| E3.1 | **组织与用户·角色权限** | 维护账号、角色、各自能看多少数据 | 要 |
| E3.2 | **主数据** | 访客类型、黑名单、可预约时段规则、校门/通行点、被访人名册 | 要 |
| E3.3 | **通知消息** | 预约流转、审核结果、异常提醒的推送（站内/短信/企微） | 要 |
| E3.4 | **系统管理** | 操作日志/留痕、参数配置、数据字典 | 要 |

## J 组 · 通用访客系统对照增补（G1–G11）

> 这一组是我方**主动拿本设计对比了市面上通用访客系统**后，建议补上的 11 项常见能力（用户 2026-10-12 已确认**全部纳入**）。它挂在既有模块上、不新开页面。

| 编号 | 大白话：补的是什么 | 业务影响 / 谁受益 | 建议默认值 | 备选口径 |
|------|--------------------|------------------|-----------|---------|
| J1 | **在校（实时）清单**：一眼看到「现在还在校园里都有谁」（谁 / 何时进 / 找谁 / 已在校多久） | 应急疏散、突发事件的关键视图 | 要（安全核心） | 可后置 |
| J2 | **证件识别**：门口刷证 / 拍照自动读姓名、证件号并与预约比对 | 核验更快更准 | 要（识别失败可手输） | 可只做手输 |
| J3 | **现场人像采集**：核验时给访客拍照留存、绑定本次记录 | 事后可追溯 | 要（仅留痕，不做人脸比对） | 可后置 |
| J4 | **随行人员逐人登记**：随行的人逐个填姓名 / 关系 / 证件号（不再只填人数） | 到访人数以明细为准 | 要 | 可只记人数 |
| J5 | **超时催离 + 批量核销**：在校超时提醒离开；离校高峰可多选批量核销 | 减少滞留、提高放行效率 | 要（阈值可配） | 可后置 |
| J6 | **被访人邀约**：老师主动发邀请码 / 链接给访客，访客凭码快速来 | 减少访客填单、对接更快 | 要 | 可后置 |
| J7 | **被访人移动端审批**：老师在手机上就能同意 / 拒绝 / 改期 | 审批不必回电脑 | 要 | 可后置 |
| J8 | **常客快登**：来过、批过且不在黑名单的访客，再来一键复用信息 | 高频访客登记更快 | 要 | 可后置 |
| J9 | **访客证 / 临时通行卡**：核验后打印访客证或发临时卡；离校回收 | 在校人员好识别 | 要 | 可用电子凭证替代 |
| J10 | **车牌识别 / 道闸联动**：识别访客车牌并对预约车牌；有设备可联动道闸放行 | 车辆通行提速 | 要（做开关预留，有设备再启用） | 无设备手工核对 |
| J11 | **个人信息保护**：授权告知 + 最小必要收集 + 留存到期脱敏 / 清除 | 合规、隐私保护 | 要（默认留存 90 天可配） | 可调期限 |

> 落点：J1 挂在「访客台账」；J2/J3/J5/J9/J10 挂在「门卫核验放行」；J4/J6/J8 挂在「访客预约」；J7 挂在「被访人审核」；J5 的阈值、J8 的常客库、J10 的开关挂在「主数据」；J11 挂在「系统管理」。详见 `02-功能模块地图.md` 与 `03-简易交互原型.html`。
