# 测试结果存放说明（test-results）

> 本目录存放首轮执行期的实测结果。目录内的卡片结果文件由对应卡片在「完成改动之后」写入；`summary.md` 由集成闭环卡汇总生成。本文件只规定格式与命名，不预置任何结果。

## 一、文件命名

| 文件 | 写入卡 | 内容 |
|------|--------|------|
| `VIS-P1-I01.md` | master 主数据全栈卡 | 13 条 TC 的实测结果 |
| `VIS-P1-I02.md` | notify 通知全栈卡 | 6 条 TC 的实测结果 |
| `VIS-P1-I03.md` | report 台账统计全栈卡 | 16 条 TC 的实测结果 |
| `VIS-P1-I04.md` | access 门户权限全栈卡 | 14 条 TC 的实测结果 |
| `VIS-P1-I05.md` | visit 来访闭环全栈卡 | 54 条 TC 的实测结果 |
| `VIS-P1-I06.md` | compliance 审计隐私全栈卡 | 4 条 TC 的实测结果 |
| `summary.md` | 集成闭环卡 | 107 条 TC 的全量汇总 |

## 二、单卡结果文件格式

````markdown
# <卡片编号> 测试结果

- 执行日期：YYYY-MM-DD
- 执行环境：docker compose，PostgreSQL 15，Node 20
- 执行人：<执行卡片的代理或人员>

## TC-XX-001 <测试点>

- 已定预期：<逐字取自 output/v1.0/测试.md>
- 执行命令：
  ```bash
  <命令>
  ```
- 实际输出：
  ```text
  <原始输出摘要，含状态码、关键字段、行数>
  ```
- 结论：通过 / 部分可达 / 未通过
- 失败处理：<未通过时填写现象、根因、修复文件、回归命令；通过时写「无」>

## TC-XX-002 ...
````

## 三、结论口径

| 结论 | 判定 |
|------|------|
| 通过 | 实际输出与已定预期逐项一致 |
| 部分可达 | 已定预期中的孤儿断言（O-01…O-04）已剔除，其余断言逐项一致；不得写成「通过」 |
| 未通过 | 任一保留断言不一致；必须附修复与回归记录，修复后重跑并改写结论 |

## 四、汇总文件格式

`summary.md` 由集成闭环卡生成，每行一条 TC：

| 卡片 | TC | 测试点 | 结论 | 结果文件 |
|------|----|--------|------|----------|
| VIS-P1-I04 | TC-PT-001 | 后台账号登录成功 | 通过 | `test-results/VIS-P1-I04.md#tc-pt-001` |

汇总表必须覆盖 107 条 TC，无缺行、无重复；封版归档卡以本表的结论统计作为 10 项检查之一。

## 五、只读输入

`output/v1.0/测试.md` 与 `output/v1.0/测试结果.md` 是设计期输入，执行期只读；实测结果不回写、不覆盖这两份文件。
